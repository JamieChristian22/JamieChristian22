## A practical 5-minute review

1. Open the README for the role that matches the position.
2. Select the named case study or demo and inspect the actual artifacts.
3. Read any assumptions, synthetic-data disclosures, and limitations.
4. Inspect the test files and the **current** GitHub Actions status, rather than assuming a badge or a past successful run proves the present code.
5. Use the repository issues or profile links if more detail is needed.

## Accuracy, sources and limitations

These repositories include educational laboratories, synthetic case studies, modeled decisions, and testable code. They are **not** represented as verified employer engagements, production deployments, or independently audited business results unless the individual project supplies that evidence.

The [portfolio asset provenance inventory](https://github.com/JamieChristian22/.github/blob/main/PORTFOLIO_ASSET_AUDIT.md) identifies data, image and document candidates that need source/rights review; it is **not** a certification of redistribution permission.
