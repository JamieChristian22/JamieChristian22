## How to contribute safely

1. Review the chosen repository's current README, `CONTRIBUTING.md` (if present), and existing issues/PRs.
2. Propose one narrowly scoped correction or improvement instead of a massive rewrite.
3. Use synthetic data and public documentation only. Never share private customer records, passwords, or unauthorized security findings.
4. Report exactly which checks you ran. A command shown in a guide is **not** proof that tests passed.
5. Submit a focused PR if the project accepts contributions. Maintainers may need time to review; there is no guarantee a suggestion will be accepted.

**Open-source learning and paid work are separate.** A public issue, contribution, or star is not a paid bounty unless funding, eligibility, acceptance criteria and payment arrangements have been expressly verified. For commissioned work, see [funded-work inquiries](FUNDED_WORK.md) and [scope-first paid services](PAID_SERVICES.md).
